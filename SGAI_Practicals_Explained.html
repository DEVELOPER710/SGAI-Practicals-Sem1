P1 – Control structures

Concepts

  • Control structure: a statement that decides which lines run and how many times. In plain words: without them a program runs top to bottom once; with them it can choose and repeat.
  • if / else: runs a block only when a condition is True, otherwise the else block. Plain words: "if it's raining, take an umbrella, else don't".
  • if / elif / else: checks several conditions in order; only the first true one runs. Plain words: a ladder – you stop at the first step that fits. That's why the percentage program checks >= 90 before >= 75.
  • Nested if: an if inside another if. Plain words: a second question you only ask after the first answer ("divisible by 5? then, divisible by 11 too?").
  • for loop: repeats once for each item of a sequence. range(a, b) gives a, a+1 … b−1 (b is excluded). Plain words: "do this for every number from 1 to 10".
  • while loop: repeats as long as a condition stays true. Plain words: "keep going until…". You must change the variable inside, or it loops forever.
  • break: exits the loop immediately. continue: skips to the next round.
  • for–else: the else runs only if the loop finished without break. Plain words: "searched everything and found nothing".
  • Operators: % = remainder (10 % 3 = 1), so n % i == 0 means "i divides n exactly". == compares, = assigns.
  • ord() / chr(): ord('A') = 65 (the character's ASCII code), chr(66) = 'B'.

Code

Python
# ---------- 1. PRIME NUMBER (for loop + if-else, for-else) ----------
n = int(input("Number: "))              # input() gives text, int() turns it into a number
for i in range(2, n):                    # try every divisor from 2 to n-1 (range excludes n)
    if n % i == 0:                       # % = remainder; 0 means i divides n exactly
        print("Not prime")
        break                            # found a divisor, stop the loop
else:                                    # for-else: runs only if the loop never hit break
    print("Prime" if n > 1 else "Not prime")   # 0 and 1 are not prime

# ---------- 2. DAYS IN A MONTH (if-elif-else) ----------
m = int(input("Month: "))
if m == 2:
    print("28 days (29 in a leap year)")   # February
elif m in (4, 6, 9, 11):                 # April, June, September, November
    print("30 days")
else:                                    # all other months
    print("31 days")

# ---------- 3. MENU CALCULATOR (while loop + if-elif) ----------
a, b = float(input("a: ")), float(input("b: "))   # float() allows decimals
c = 0                                    # start at 0 so the loop runs at least once
while c != 5:                            # keep showing the menu until the user picks 5 (Exit)
    c = int(input("1.+ 2.- 3.* 4./ 5.Exit: "))
    if c == 1: print(a + b)
    elif c == 2: print(a - b)
    elif c == 3: print(a * b)
    elif c == 4: print(a / b)

# ---------- 4. REMARKS FROM PERCENTAGE (if-elif-else ladder) ----------
p = int(input("Percentage: "))
if p >= 90: print("Excellent")           # checked top to bottom; the first true one runs
elif p >= 75: print("Very Good")         # so 82 fails >= 90 and stops here
elif p >= 60: print("Good")
elif p >= 40: print("Average")
else: print("Fail")                      # below 40

# ---------- 5. PRINT 30 TO 1 (while loop) ----------
i = 30
while i >= 1:                            # repeat while i is still 1 or more
    print(i)
    i -= 1                               # same as i = i - 1; without it the loop never ends

# ---------- 6. FIBONACCI UP TO n TERMS (while loop) ----------
n = int(input("Terms: "))
a, b, i = 0, 1, 0                        # first two terms, and a counter
while i < n:
    print(a)
    a, b = b, a + b                      # next term = sum of previous two; both update at once
    i += 1                               # one more term printed

# ---------- 7. ASCII VALUES OF A TO Z ----------
ch = 'A'
while ch <= 'Z':                         # letters compare in alphabetical order
    print(ch, ":", ord(ch))              # ord() gives the character's ASCII code (A = 65)
    ch = chr(ord(ch) + 1)                # chr() turns code+1 back into the next letter

# ---------- 8. NUMBER TRIANGLE PATTERN (nested for) ----------
r = int(input("Rows: "))
for i in range(1, r + 1):                # outer loop = which row
    for j in range(1, i + 1):            # inner loop = numbers 1..row number
        print(j, end=" ")                # end=" " keeps them on the same line
    print()                              # move to the next line after each row

# ---------- 9. TABLES OF 5 TO 10 (nested for) ----------
for i in range(5, 11):                   # 5 to 10 (11 is excluded)
    for j in range(1, 11):               # multiply by 1 to 10
        print(i, "x", j, "=", i * j)

# ---------- 10. DIVISIBLE BY 5 AND/OR 11 (nested if) ----------
n = int(input("Number: "))
if n % 5 == 0:                           # outer question: divisible by 5?
    if n % 11 == 0: print("Divisible by both")   # inner question: also by 11?
    else: print("Only by 5")
else:
    if n % 11 == 0: print("Only by 11")
    else: print("Neither")

P2 – Dictionary, List and Tuple

Concepts

Type Syntax Ordered Mutable (changeable) Plain-language idea Used here for
List [85, 90, 88] Yes Yes A shopping list you can add to, edit, cross out Marks; all bill entries
Tuple ("Rahul", [85, 90]) Yes No A printed receipt – fixed once made (name, marks); one bill entry
Dictionary {1: ("Rahul", […])} Yes (Python 3.7+) Yes A phone book – look up a value by its key roll → record; item → stock
  • Mutable vs immutable: a mutable object can be changed after creation; an immutable one cannot. Plain words: a whiteboard vs a printed page.
  • Key–value pair: in a dictionary every key (unique, immutable, e.g. roll number) maps to a value. Lookup by key is very fast.
  • The viva trick: a tuple can't change, but if it holds a list, that list can still change. So in ("Rahul", [85, 90]) the name is locked but the marks can be updated.
  • Tuple unpacking: name, q, p = ("rice", 5, 60) puts each item in its own variable. for r, (n, m) in s.items() does this inside a loop.
  • Useful methods: list – append(), remove(), pop(); dict – items() (key + value pairs), keys(), values(), get(key, default).
  • map() and split(): "85 90 88".split() → ["85", "90", "88"]; map(int, …) turns each into a number.

Code: Student Record Manager

Python
# Dictionary: key = roll number, value = tuple (name, list_of_marks)
# Tuple keeps the name fixed; the list inside it can still be changed
s = {1: ("Rahul", [85, 90, 88])}

while True:                                          # menu repeats until the user picks Exit
    c = input("1.Add 2.Avg>80 3.Update 4.Exit: ")

    if c == "1":                                     # ADD a student
        r = int(input("Roll: "))                     # roll number = the dictionary key
        s[r] = (input("Name: "),                     # store a new tuple under that key
                list(map(int, input("Marks: ").split())))   # "85 90 88" -> [85, 90, 88]

    elif c == "2":                                   # SHOW students with average above 80
        for r, (n, m) in s.items():                  # items() gives (key, value); unpack the tuple into n, m
            if sum(m) / len(m) > 80:                 # average = total / number of marks
                print(r, n)

    elif c == "3":                                   # UPDATE marks of one student
        r = int(input("Roll: "))
        s[r][1][:] = map(int, input("New marks: ").split())   # s[r][1] = the marks list; [:] = replaces its contents in place

    else:                                            # 4 (or anything else) = Exit
        break

Code: Grocery Billing

Python
stock = {"rice": 50, "milk": 20}                     # dictionary: item -> quantity available
price = {"rice": 60, "milk": 30}                     # dictionary: item -> price per unit
bill = []                                            # list that will hold one tuple per purchase

while (item := input("Item (done): ")) != "done":    # := reads the input and checks it in one line
    q = int(input("Qty: "))
    if q <= stock.get(item, 0):                      # get() returns 0 for unknown items instead of crashing
        bill.append((item, q, price[item]))          # tuple = (name, qty, rate), fixed once billed
        stock[item] -= q                             # update the stock dictionary
    else:
        print("Insufficient stock")

print(bill)                                          # all bill entries
print("Total =", sum(q * p for _, q, p in bill))     # qty x rate for every entry, added up (_ ignores the name)
print("Stock:", stock)                               # remaining stock

P3 – Data analysis with Pandas and Matplotlib

Concepts

  • Library: ready-made code you import instead of writing it yourself. import pandas as pd loads Pandas under the short name pd.
  • Pandas: a library for data manipulation and analysis. Plain words: Excel inside Python.
  • DataFrame: a 2-D labelled table of rows and columns. Series: a single column of it. d["Maths"] is a Series; d[["Maths", "Science"]] (double brackets) is a smaller DataFrame.
  • CSV (Comma-Separated Values): a plain-text table where each line is a row and commas separate columns. pd.read_csv() loads it into a DataFrame.
  • head(): first 5 rows. describe(): summary statistics per numeric column – count, mean, std (standard deviation, how spread out the values are), min, 25%/50%/75% (quartiles; 50% = median), max.
  • axis: axis=0 works down each column (e.g. average of each subject); axis=1 works across each row (e.g. average of each student).
  • Matplotlib (pyplot): a library for drawing charts. plt.show() displays the figure.
  • Which chart when:
    • Bar chart – compare values across categories (each student's average).
    • Line chart – show a trend or compare series across the same x-points (subjects across students).
    • Histogram – show the distribution of one variable: how many values fall in each range (bin).
    • Pie chart – show each part's share of a whole, as percentages.

Code

Python
import pandas as pd, matplotlib.pyplot as plt       # pd = data tables, plt = charts

d = pd.read_csv("students.csv")                     # load the CSV into a DataFrame (a table)
print(d.head())                                      # first 5 rows
print(d.describe())                                  # count, mean, std, min, quartiles, max of each number column

# new column: average of the 3 subjects for each student (axis=1 = across the row)
d["Average"] = d[["Maths", "Science", "English"]].mean(axis=1)
print(d[["Name", "Average"]])                        # double brackets = pick several columns

# BAR CHART: compare each student's average
plt.bar(d["Name"], d["Average"])
plt.show()                                           # opens the chart; close it to continue

# LINE CHART: one line per subject across all students
for s in ["Maths", "Science", "English"]:
    plt.plot(d["Name"], d[s], marker="o", label=s)  # marker = dot on each point, label = name in the legend
plt.legend()                                         # show the key (which colour is which subject)
plt.show()

# HISTOGRAM: how many students fall in each range of Maths marks
plt.hist(d["Maths"], bins=5)                         # bins = number of ranges
plt.show()

# PIE CHART: each student's share of the total of averages
plt.pie(d["Average"], labels=d["Name"], autopct="%1.1f%%")   # autopct prints the % with 1 decimal
plt.show()

d.to_csv("students_cleaned.csv", index=False)       # save the table with the new column (index=False skips row numbers)

P4 – Generative models and the Autoencoder

Concepts

  • Generative model: a model that learns the probability distribution of its training data and can produce new samples from it. Plain words: it studies thousands of examples until it can make convincing new ones.
  • Discriminative vs generative: a discriminative model labels data ("this is a cat"); a generative model creates data (draws a new cat).
  • Neural network: layers of connected units (neurons); each multiplies its inputs by learned weights, adds them and applies an activation function. Training = adjusting the weights to reduce the error.
  • Autoencoder: a neural network trained to copy its input to its output through a narrow middle layer.
    • Encoder compresses the image: 784 pixels → 32 numbers.
    • Latent space / bottleneck: those 32 numbers – a compressed summary of the image.
    • Decoder rebuilds the 784 pixels from the 32 numbers.
    • Plain words: describe a photo in 32 words, then redraw it from only those words. To do this well it must learn what matters.
  • Unsupervised learning: no labels needed – the input itself is the target (fit(x, x)).
  • MNIST: 70,000 grayscale 28×28 images of handwritten digits (60,000 train, 10,000 test). 28 × 28 = 784 pixels.
  • Normalisation: dividing pixel values (0–255) by 255 to get 0–1. Plain words: putting everything on the same small scale makes training stable.
  • Dense layer: every neuron connects to every input. ReLU activation = max(0, x). Sigmoid squashes output into 0–1, which matches pixel values.
  • Loss (binary cross-entropy): measures how different the rebuilt image is from the original. Optimizer (Adam): the method that adjusts weights to lower the loss.
  • Epoch: one full pass over the training data. Batch size: how many images are processed before each weight update.
  • Uses: denoising, compression, anomaly detection, data augmentation. A variational autoencoder (VAE) is the version built specifically for generating new images.
  • Other Gen-AI models (theory part): GPT = Transformer (text); DALL·E / Stable Diffusion = diffusion models (images); Pix2Pix / CycleGAN = GANs, a generator vs a discriminator (image-to-image); WaveNet / Tacotron (speech); MusicLM (music); Sora (video).

Code

Python
import matplotlib.pyplot as plt
from tensorflow import keras                         # Keras = easy way to build neural networks

# Load MNIST: (train images, labels), (test images, labels); labels thrown away with _ (not needed)
(x, _), (t, _) = keras.datasets.mnist.load_data()   # downloads once, then uses the saved copy

# Flatten each 28x28 image into 784 numbers, and scale pixels 0-255 -> 0-1 (normalisation)
x, t = x.reshape(-1, 784) / 255, t.reshape(-1, 784) / 255

# Build the autoencoder: input 784 -> ENCODER 32 (bottleneck / latent space) -> DECODER 784
m = keras.Sequential([
    keras.Input((784,)),
    keras.layers.Dense(32, activation="relu"),       # encoder: compresses the image to 32 numbers
    keras.layers.Dense(784, activation="sigmoid"),   # decoder: rebuilds 784 pixels (sigmoid keeps them 0-1)
])

m.compile("adam", "binary_crossentropy")            # optimizer = Adam, loss = how different output is from input
m.fit(x, x, epochs=5, batch_size=256)                # input = target (unsupervised); 5 passes, 256 images per step

o = m.predict(t)                                     # rebuild test images the model has never seen

# Show 5 originals (top row) and their reconstructions (bottom row)
for i in range(5):
    plt.subplot(2, 5, i + 1)                         # grid of 2 rows x 5 columns, position i+1
    plt.imshow(t[i].reshape(28, 28), cmap="gray")    # turn 784 numbers back into a 28x28 image
    plt.subplot(2, 5, i + 6)                         # same column, bottom row
    plt.imshow(o[i].reshape(28, 28), cmap="gray")
plt.show()

If MNIST is given as a file (no internet), replace the load_data() line with: import numpy as np; f = np.load("mnist.npz"); x, t = f["x_train"], f["x_test"]

P5 – Personal website with HTML/CSS and Gen-AI

Concepts

  • HTML (HyperText Markup Language): the markup language that defines a web page's structure and content using tags. Plain words: the skeleton – headings, paragraphs, images.
  • Tag / element: <h1>Hello</h1> – an opening tag, content, a closing tag. Some have no closing tag (<img>). Attributes add details: src (image file), href (link target), class (a name CSS can target).
  • Page skeleton: <!DOCTYPE html> (tells the browser it's HTML5) → <html> → <head> (title, links to CSS, meta info – not shown on the page) + <body> (everything visible).
  • CSS (Cascading Style Sheets): rules that control presentation – colours, fonts, spacing, layout. Plain words: the clothes on the skeleton.
  • CSS rule: selector { property: value; }. Selectors: h1 (all h1 tags), .card (class="card"), #count (id="count").
  • Three ways to add CSS: inline (style="…" on a tag), internal (<style> in the head), external (a .css file linked with <link> – the best, reusable).
  • Responsive design: the viewport meta tag and @media rules make the page fit phones too.
  • Role of Generative AI: tools like ChatGPT or Copilot turn a prompt ("make a dark portfolio with a projects section") into starter HTML/CSS. You still review and personalise it.
  • Hosting: putting files on a server so anyone can open the link. GitHub Pages serves a repo's files for free at username.github.io/repo; Netlify lets you drag and drop a folder.

P6 – Rule-based chatbot with NLP

Concepts

  • NLP (Natural Language Processing): the branch of AI that lets computers read, understand and generate human language. Plain words: teaching a computer to deal with normal sentences, not just commands.
  • Chatbot: a program that holds a conversation. Rule-based chatbots follow hand-written rules; AI/ML chatbots (like ChatGPT) learn from data.
  • Regular expression (regex): a pattern describing text. Plain words: a search template.
    • . = any character, * = zero or more times, so .* = "anything".
    • ( ) = a capture group: it saves the matched part so it can be reused.
    • | = OR: hi|hello matches either.
    • \b = a word boundary, so hi\b matches "hi" but not "history".
  • Pattern–response pairs: each rule is [pattern, [possible replies]]. The bot tries the patterns in order and uses the first match; if a rule has several replies, it picks one at random.
  • %1: inserts the text caught by the first ( ) group. "my name is Chinmay" with my name is (.*) → %1 = "chinmay" (NLTK lowercases the captured text while applying reflections).
  • Reflections: a dictionary that swaps pronouns in the captured text so the reply sounds natural: I → you, my → your, am → are. "I need my book" → "Why do you need your book?"
  • Default response: the catch-all (.*) matches anything, so it must be the last rule; otherwise it would answer everything.
  • NLTK (Natural Language Toolkit): a Python NLP library; nltk.chat.util provides Chat and reflections.
  • Limitations (viva): no memory of earlier messages, no real understanding, can't learn, breaks on typos or phrasing nobody wrote a rule for.

Code

Python
from nltk.chat.util import Chat, reflections         # Chat = rule-based bot, reflections = pronoun swaps (my -> your)

# Each rule = [regex pattern, [possible replies]]. Rules are tried top to bottom; first match wins.
# (.*) = "anything", and it is captured; %1 puts the captured text into the reply.
pairs = [
    [r"my name is (.*)", ["Hello %1!"]],                       # greets the user by name
    [r"(hi|hello|hey)\b(.*)", ["Hello! How can I help?"]],     # | = OR, \b = whole word only
    [r"(.*)your name(.*)", ["I am a chatbot."]],
    [r"how are you(.*)", ["I'm fine!"]],
    [r"i feel (.*)", ["Why do you feel %1?"]],                 # reflection: "i feel my exam..." -> "your exam"
    [r"i need (.*)", ["Why do you need %1?"]],                 # reflection: "i need my book" -> "your book"
    [r"(.*)nlp(.*)", ["NLP helps computers understand language."]],
    [r"(.*)thank(.*)", ["You're welcome!"]],
    [r"quit", ["Bye!"]],                                       # matched before the default so "quit" says Bye
    [r"(.*)", ["Sorry, I didn't understand."]],                # DEFAULT reply: matches anything, so it must be LAST
]

Chat(pairs, reflections).converse()                  # build the bot and start the chat loop; type "quit" to exit

Example run: hello → Hello! How can I help? · my name is Chinmay → Hello chinmay! · i need my book → Why do you need your book? · asdf → Sorry, I didn't understand.

P8 – Web scraping

Concepts

  • Web scraping: automatically extracting data from web pages with a program. Plain words: a script that reads a website and copies the bits you want into a table, instead of you copy-pasting by hand.
  • HTTP request: the message a browser (or script) sends to a server asking for a page. GET = "give me this page". The server replies with a status code and the page's HTML.
    • 200 = OK, 403 = Forbidden (blocked), 404 = Not found, 500 = server error.
  • requests library: sends HTTP requests from Python. requests.get(url).text = the page's HTML as a string.
  • User-Agent header: tells the server which browser is asking. Some sites block requests that don't look like a browser, so we send Mozilla/5.0.
  • Parsing: turning raw HTML text into a structure (a tree of tags) you can search. BeautifulSoup does this; "html.parser" is Python's built-in parser.
  • find() / find_all(): find_all("h2") returns every <h2> tag; .text (or .get_text()) gives the words inside it. News headlines are usually in <h2> tags.
  • Storing data: a pandas DataFrame organises the results; to_csv() saves them as a spreadsheet file.
  • Ethics (viva): check the site's robots.txt and terms, don't flood it with requests, don't collect personal data. Pages built by JavaScript need a tool like Selenium, because requests only gets the initial HTML.

Code

Python
import requests, pandas as pd                        # requests = fetch web pages, pandas = make a table / CSV
from bs4 import BeautifulSoup                        # BeautifulSoup = parse (read) HTML

url = "https://www.bbc.com/news"
headers = {"User-Agent": "Mozilla/5.0"}              # pretend to be a browser so the site doesn't block us

html = requests.get(url, headers=headers).text       # 1. REQUEST: GET the page; .text = its HTML as a string
s = BeautifulSoup(html, "html.parser")               # 2. PARSE: turn the HTML into a searchable tree

# 3. EXTRACT: every <h2> tag holds a headline; keep the text of non-empty ones, first 10 only
#    (list comprehension = a for loop that builds a list in one line)
headlines = [h.text for h in s.find_all("h2") if h.text][:10]

df = pd.DataFrame({"Headline": headlines})           # 4. STORE: one-column table
print(df)
df.to_csv("bbc_headlines.csv", index=False)          # save as a CSV file

If a saved HTML file is given instead of a URL, replace the requests.get line with html = open("page.html", encoding="utf-8").read().

P9 – JavaScript counter app and debugging

Concepts

  • JavaScript (JS): a client-side scripting language that runs in the browser and adds logic and interactivity. Plain words: HTML is the skeleton, CSS the clothes, JS the muscles – it makes things happen when you click.
  • DOM (Document Object Model): the browser's tree of objects representing the page. JS reads and changes the page through it. document.getElementById("count") grabs the element with id="count".
  • Variables: let = can be reassigned (the count changes); const = can't be reassigned (the reference to an element stays fixed). Avoid the old var.
  • State: the data the app remembers right now – here, the number count. The UI must be updated whenever state changes.
  • Event / event listener: an event is something that happens (a click, a key press). addEventListener("click", fn) says "when this is clicked, run fn". Plain words: a doorbell wired to an action.
  • Function: a named, reusable block of code. () => { … } is an arrow function, a short way to write one.
  • textContent: the text inside an element; setting it changes what's shown.
  • Debugging: finding and fixing errors.
    • Syntax error: the code breaks the language's grammar and won't run at all (a missing }).
    • Runtime error: the code is valid but crashes while running (calling a method on null because the id was misspelt).
    • Logical error: no crash, but the result is wrong (count + "1" gives "01", "011" because "1" is text).
  • Debugging tools: console.log() prints values; DevTools (F12) → Console shows logs and errors with line numbers; Sources tab → breakpoint (click a line number) pauses the code there so you can inspect variables and step line by line (F10).

Code (one file, index.html)

HTML
<h1>Counter App</h1>
<p id="count">0</p>                               <!-- shows the number; id lets JS find it -->
<button id="inc">Increment</button>
<button id="reset">Reset</button>

<script>                                          // JS goes AFTER the elements so they already exist
  let count = 0;                                  // STATE: the current number (let = can change)
  const c = document.getElementById("count");     // DOM ACCESS: grab the <p> (const = won't be reassigned)

  // EVENT LISTENER: when Increment is clicked, run this arrow function
  document.getElementById("inc").addEventListener("click", () => {
    console.log("Before:", count);                // DEBUGGING: value before (see F12 -> Console)
    count++;                                      // add 1 to the state
    console.log("After:", count);                 // value after
    c.textContent = count;                        // UPDATE the page to show the new number
  });

  // EVENT LISTENER: when Reset is clicked, go back to 0

P10a – Speech-to-text with the Google Speech API

Concepts

  • Speech-to-text (STT) / Automatic Speech Recognition (ASR): converting spoken audio into written text. Plain words: automatic typing of what someone says, like YouTube auto-captions.
  • How it works:
    1. Audio input – a recording (WAV, FLAC) or live microphone.
    2. Preprocessing – noise reduction, then feature extraction: turning sound waves into numbers that describe them (e.g. MFCCs, a fingerprint of the sound in short time slices).
    3. Model – a deep neural network trained on huge amounts of speech maps those features to words.
    4. Output – the transcribed text.
  • API (Application Programming Interface): a ready-made service your code can call. Plain words: a counter where you hand in a request and get a result back, without knowing what happens in the kitchen.
  • Google Web Speech API: Google's free cloud speech service. The audio is sent over the internet to Google, so internet is required.
  • SpeechRecognition library: a Python wrapper that handles loading audio and calling several engines; recognize_google() uses Google's.
  • Audio formats: WAV is uncompressed and FLAC is lossless, so the library reads them reliably. MP3 must be converted first.
  • Exceptions: errors your code can catch with try/except instead of crashing.
    • UnknownValueError – the audio was unclear, silent or too noisy.
    • RequestError – no internet or the service failed.
  • Applications: voice assistants (Alexa, Google Assistant), automatic captions, meeting transcription, accessibility for people with hearing or motor impairments.

Code

Python
import speech_recognition as sr                      # SpeechRecognition library (talks to Google's API)

r = sr.Recognizer()                                  # the object that does the recognition

with sr.AudioFile("Conference.wav") as f:            # open the WAV file (closed automatically after the block)
    audio = r.record(f)                              # read the whole file into 'audio'

try:                                                 # try: things that might fail go here
    print(r.recognize_google(audio))                 # send audio to Google over the internet, print the text
except sr.UnknownValueError:                         # Google got the audio but couldn't make out any words
    print("Could not understand audio")
except sr.RequestError:                              # no internet, or Google's service failed
    print("API/Internet error")

Optional: r.recognize_google(audio, language="en-IN") for Indian English.

P10b – Tweet sentiment analysis with VADER

Concepts

  • Sentiment analysis: an NLP technique that decides whether text expresses positive, negative or neutral emotion. Plain words: a mood detector for sentences – used on reviews, tweets and feedback.
  • Lexicon: a dictionary of words with sentiment scores ("amazing" strongly positive, "terrible" strongly negative).
  • VADER (Valence Aware Dictionary and sEntiment Reasoner): a pre-trained, lexicon- and rule-based analyser built for social media. It needs no training data. Its rules handle:
    • negation ("not good" becomes negative),
    • intensifiers ("very good" > "good"),
    • CAPS and "!!!" for emphasis, plus slang and emojis.
  • polarity_scores() output: pos, neg, neu = proportions of the text that are positive, negative, neutral (they add up to 1); compound = one overall score normalised from −1 (most negative) to +1 (most positive).
  • Classification thresholds: compound ≥ +0.05 → positive; ≤ −0.05 → negative; in between → neutral.
  • Preprocessing / cleaning: removing noise before analysis – URLs, @mentions, symbols – using regex: re.sub(pattern, replacement, text) replaces every match.
  • Lambda: a tiny one-line nameless function. lambda c: c * 2 = "take c, return c × 2". apply() runs a function on every value of a column.
  • Accuracy: correct predictions ÷ total × 100, possible only if the CSV has true labels.
  • Viva point: cleaning removes emojis, "!" and CAPS, which VADER could have used. Sarcasm ("great, another Monday") also fools it.

Code

Python
import pandas as pd, re                               # pandas = table, re = regular expressions (text patterns)
from nltk.sentiment import SentimentIntensityAnalyzer # VADER

df = pd.read_csv("tweets.csv")                       # load tweets (if the header is on row 2: header=1)
sia = SentimentIntensityAnalyzer()                   # create VADER (loads its word list)

# CLEAN each tweet: remove links (http...), mentions (@name) and anything that isn't a letter/space; then lowercase
# lambda t: ... = a tiny one-line function; apply() runs it on every row of the column
df["clean"] = df["tweetText"].apply(lambda t: re.sub(r"http\S+|@\w+|[^a-zA-Z\s]", "", str(t)).lower())

# SCORE: polarity_scores gives {neg, neu, pos, compound}; keep compound (-1 to +1)
df["compound"] = df["clean"].apply(lambda t: sia.polarity_scores(t)["compound"])

# LABEL: >= 0.05 positive, <= -0.05 negative, otherwise neutral
df["sentiment"] = df["compound"].apply(lambda c: "positive" if c >= 0.05 else "negative" if c <= -0.05 else "neutral")

print(df[["tweetText", "compound", "sentiment"]])   # show results
df.to_csv("tweets_with_sentiment.csv", index=False) # save results to a new CSV

# ACCURACY (only if the file has a 'label' column): lower() so "Positive" matches "positive"; mean() of True/False = fraction correct
if "label" in df.columns:
    print("Accuracy:", (df["label"].str.lower() == df["sentiment"]).mean() * 100, "%")

If tweetText gives a KeyError, run print(df.columns) and use the column name it shows.

GitHub study assignment

Concepts

  • Version control system (VCS): software that records every change to files over time so you can see history and return to any earlier version. Plain words: unlimited "undo" plus a diary of who changed what.
  • Git: a free, distributed VCS that runs on your own computer. GitHub: a website that hosts Git repositories online and adds collaboration tools (pull requests, issues, Pages).
  • Repository (repo): a project's folder plus its entire change history.
  • Commit: a saved snapshot of changes, with an author, a timestamp, a unique ID (hash) and a message.
  • Branch: a separate line of work split off from main. Merge: joining a branch back. Pull request (PR): a request on GitHub to merge a branch, so others can review first.
  • Clone / push / pull: copy a repo to your laptop / upload your commits / download others' new commits.

Answers (3–4 sentences each)

Q1. What is GitHub, and how is it different from Git? Git is a free, open-source distributed version control system that runs on your own computer and tracks changes through commits and branches. GitHub is a cloud platform built on top of Git that hosts repositories online. It adds collaboration features such as pull requests, issues, code review and GitHub Pages. In short, Git is the tool, and GitHub is a service that hosts Git repositories so teams can work together.

Q2. Define repository. What are public and private repositories? A repository is a storage location for a project that holds all its files, folders and the full history of changes. A public repository can be viewed and cloned by anyone on the internet, though only collaborators can push changes. A private repository is visible only to its owner and invited collaborators. Public repos suit open-source work and portfolios; private ones suit personal, academic or company code.

Q3. What is a commit? Explain its purpose. A commit is a snapshot of changes made to a repository at a point in time. Each commit records the changes, the author, a timestamp, a unique ID and a message describing what changed. Commits build the project's history, so you can see who changed what and when. If something breaks, you can compare versions or go back to an earlier commit.

Q4. What is a branch and why is it used? A branch is an independent line of development split off from the main code. It lets you build a feature, fix a bug or experiment without affecting the stable main branch. Several people can work on different branches at the same time. When the work is ready, the branch is merged back, usually through a reviewed pull request.
